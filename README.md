# Authentik BioKey

[GitHub](https://github.com/sqsergio1995/authentik-biometric) ·
[Gitea mirror](https://gitea.bluerippleprime.com/sergio/authentik-biometric) ·
[Project page](https://bluerippleprime.com/authentik-biokey)

Authentik BioKey turns a Linux laptop's TPM 2.0 and fingerprint reader into a
device-bound FIDO2 passkey for Authentik. Chromium, Chrome, and Firefox see it
as a virtual security key, so Authentik can request a fingerprint instead of a
six-digit TOTP code. No browser extension and no biometric data upload are
required.

```text
Authentik login page
        |
        | WebAuthn / CTAP2
        v
Chromium or Firefox -> Linux UHID virtual key
                              |        |
                              v        v
                         TPM signing  fprintd
```

Private signing keys are generated by the TPM and are not exported. The local
metadata file contains relying-party and user labels, public keys, and opaque
TPM credential handles. Fingerprint matching remains inside `fprintd` and the
reader; Authentik receives only a standards-based WebAuthn assertion.

## Requirements

- Linux with `/dev/tpmrm0` and the `uhid` kernel module
- A fingerprint reader supported by `fprintd`, with a finger already enrolled
- Go 1.24 or newer when building from source (not needed for the included
  x86-64 binary)
- `notify-send`, systemd user services, and a native or FIDO-enabled browser
- Authentik served over HTTPS

The implementation is experimental and has not completed FIDO certification or
an independent security audit. Keep an Authentik recovery method (a hardware
security key or static recovery codes) before removing TOTP.

## Install

Install distribution prerequisites first.

Fedora:

```bash
sudo dnf install golang fprintd fprintd-pam libnotify
fprintd-enroll
```

Debian or Ubuntu:

```bash
sudo apt install golang-go fprintd libpam-fprintd libnotify-bin
fprintd-enroll
```

Then run the installer with the exact public URL of your Authentik instance:

```bash
./install.sh --authentik-url https://auth.example.com
```

The installer builds a static binary, installs a user service and a narrowly
scoped UHID access rule, then enables the tray application. If TPM group access
has to be added, log out and back in and start it with:

```bash
systemctl --user start authentik-biometric.service
```

The daemon fails closed unless an exact Authentik relying-party hostname is
configured. To allow a second legitimate Authentik hostname, edit
`~/.config/authentik-biometric/config.env` as a comma-separated list and restart
the service:

```dotenv
AUTHENTIK_BIOMETRIC_RP_IDS=auth.example.com,login.example.net
```

## Configure Authentik

The included blueprint creates two isolated flows without replacing your
current login flow:

- `authentik-biokey-enrollment` registers a discoverable WebAuthn credential
  and requires user verification.
- `authentik-biokey-login` performs passwordless WebAuthn login and requires a
  verified fingerprint.

In Authentik, open **Admin interface > Customization > Blueprints**, import
`authentik/biometric-passwordless.yaml`, and apply it. Authentik 2025.12 or
newer is recommended.

### Enroll safely

1. Keep your existing session open and create Authentik static recovery codes.
2. Confirm BioKey is running: `systemctl --user status authentik-biometric`.
3. Visit `https://auth.example.com/if/flow/authentik-biokey-enrollment/`.
4. Choose the Authentik BioKey/security-key option and touch the fingerprint
   reader when the desktop prompt appears.
5. In a private browser window, test
   `https://auth.example.com/if/flow/authentik-biokey-login/`.

After the private-window test succeeds, either:

- edit your existing Identification stage and set **Passwordless flow** to
  `Authentik BioKey passwordless login`; or
- make that flow the authentication flow for a dedicated Authentik Brand.

To keep a password but replace only Google Authenticator, add the blueprint's
`authentik-biokey-validation` stage after your Password stage and before the
User Login stage. Do this in a copy of the current flow first. Do not remove
TOTP until the copied flow and recovery path have both been tested.

Authentik's current WebAuthn documentation explains the same setup-stage and
validation-stage relationship:

- https://docs.goauthentik.io/add-secure-apps/flows-stages/stages/authenticator_webauthn/
- https://docs.goauthentik.io/add-secure-apps/flows-stages/stages/authenticator_validate/

## Use and troubleshoot

Any WebAuthn registration or sign-in for the configured Authentik hostname
triggers a critical desktop notification and a 30-second fingerprint prompt.
The tray icon can temporarily disable the virtual key and automatically yields
to a physical YubiKey.

```bash
AUTHENTIK_BIOMETRIC_RP_IDS=auth.example.com \
  ~/.local/bin/authentik-biometric --check
journalctl --user -u authentik-biometric -f
```

If the browser does not show the key, confirm `/dev/hidraw*` appears after the
service starts. Snap browsers may also need their `u2f-devices` interface
connected. Flatpak browsers may need explicit device access; a native browser
package is the simplest supported path.

Credential metadata is stored with mode `0600` under
`~/.local/share/authentik-biometric/credentials.json`. TPM-bound credentials do
not roam to another laptop and normally stop working after a TPM clear or
motherboard replacement. Delete the corresponding WebAuthn device in Authentik
before re-enrolling.

## Build and test

```bash
go test ./...
go build -trimpath -o authentik-biometric ./main.go
```

Hardware testing needs a real TPM, a supported fingerprint reader, `/dev/uhid`,
and a browser. Unit tests deliberately use no biometric or TPM hardware.

## Security boundaries

- Exact RP-ID allowlisting prevents this Authentik-specific daemon from
  registering credentials or signing assertions for unrelated websites.
- The Authentik stage requests `userVerification=required`; the daemon sets the
  WebAuthn UV flag only after `fprintd-verify` succeeds.
- The user service uses a restrictive umask and systemd sandboxing.
- Authentik still controls identity, sessions, access policy, and recovery.
- A compromised root account, kernel, browser, `fprintd`, or TPM firmware is
  outside this application's protection boundary.
